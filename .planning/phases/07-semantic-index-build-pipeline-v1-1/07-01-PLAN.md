<objective>
Extend MCPackEngine with a non-blocking semantic index build pipeline. When MCPackConfig.embeddings is configured, the engine constructor kicks off a fire-and-forget Promise that:
1. Composes per-tool indexing strings (`name + " " + description + " " + paramNames.join(" ")`).
2. Calls the configured EmbeddingProvider once with the entire batch of strings.
3. Stores the resulting vectors as a `Map<string, Float32Array>` keyed by tool name.

The constructor returns synchronously regardless of embeddings config. tools/list keeps v1.0 latency. A new public-on-engine method `isIndexReady()` lets Phase 8 branch on build state without awaiting. When embeddings is absent, the engine code path is byte-identical to v1.0+Phase-6.

Purpose: Phase 7 owns the build state; Phase 8 will consume it for the hybrid query path. This plan ships only the build pipeline + readiness check — no query routing changes (handleSearchTools body is byte-identical to v1.0).

import type { Tool } from '@modelcontextprotocol/sdk/types.js';

/**
 * Extract parameter names from a tool's inputSchema.properties keys.
 *
 * Returns the property names in original case, in declaration order, with no
 * tokenization or deduplication. The semantic embedding model owns its own
 * tokenizer; pre-stripping or splitting the names here would degrade retrieval
 * recall (per sbert.net "Don't preprocess your text" guidance).
 *
 * Mirrors the guard pattern in `src/index-builder.ts:extractSchemaKeywords` but
 * does NOT tokenize — that's the sibling adapter package's model's concern.
 *
 * @internal Module-private; not re-exported from `src/index.ts`.
 */
export function extractParameterNames(inputSchema: Tool['inputSchema']): string[] {
  if (!inputSchema || !('properties' in inputSchema) || !inputSchema.properties) {
    return [];
  }
  return Object.keys(inputSchema.properties);
}

/**
 * Compose the per-tool indexing string used by the semantic index build.
 *
 * Format (locked by 07-CONTEXT.md decision §"Indexing String Composition" + DEC-v11-01):
 *   `tool.name + " " + (tool.description ?? "") + " " + parameter-names-joined-by-space`
 *
 * Trimmed to collapse trailing/leading spaces when description is empty or
 * the tool has no parameters. Original case preserved (no lowercasing) — the
 * embedding model's tokenizer handles case folding internally.
 *
 * @internal Module-private; not re-exported from `src/index.ts`.
 */
export function buildIndexingString(tool: Tool): string {
  const name = tool.name;
  const description = tool.description ?? '';
  const paramNames = extractParameterNames(tool.inputSchema);
  return `${name} ${description} ${paramNames.join(' ')}`.trim();
}
```

      /**
       * Build the semantic index by composing per-tool indexing strings, batching
       * them through the configured EmbeddingProvider, and storing the resulting
       * vectors as Float32Array keyed by tool name.
       *
       * Single batch call (per DEC-v11-01 + 07-CONTEXT.md §"Indexing String Composition"):
       * pass N strings, expect N vectors, parallel-array semantics.
       *
       * Validates:
       *   - vectors.length === tools.length (parallel-array contract)
       *   - all vectors share the same dimensionality (provider contract)
       *
       * Empty tool surface is a no-op (assigns empty Map, returns).
       *
       * Throws on contract violation. Caller (constructor kickoff) attaches `.catch`
       * to log the failure and leave `semanticIndex` null.
       *
       * @internal Phase 7 — Phase 8 consumes the resulting `semanticIndex` for cosine similarity.
       */
      private async buildSemanticIndex(
        tools: Tool[],
        provider: EmbeddingProvider,
      ): Promise<void> {
        if (tools.length === 0) {
          // Empty surface: build is a no-op. Mark "ready" with empty map.
          // Defense-in-depth: both wrap.ts and build.ts throw on empty tools at
          // their entry points, so this branch is unreachable in practice — but
          // direct MCPackEngine construction (e.g., in tests) may exercise it.
          this.semanticIndex = new Map();
          return;
        }

        const indexingStrings = tools.map((t) => buildIndexingString(t));
        const vectors = await provider(indexingStrings);

        // Validate parallel-array contract.
        if (vectors.length !== tools.length) {
          throw new Error(
            `MCPack: provider returned ${vectors.length} vectors for ${tools.length} tools (parallel-array contract violation)`,
          );
        }

        // Validate dimension consistency across the batch.
        if (vectors.length > 0) {
          const dim = vectors[0]!.length;
          for (let i = 1; i < vectors.length; i++) {
            if (vectors[i]!.length !== dim) {
              throw new Error(
                `MCPack: provider returned vectors of inconsistent dimensions (vector[0]=${dim}, vector[${i}]=${vectors[i]!.length})`,
              );
            }
          }
        }

        // Assemble vector store. Wrap each number[] in Float32Array for dense
        // contiguous storage (Phase 8 cosine-similarity will want this).
        this.semanticIndex = new Map(
          tools.map((t, i) => [t.name, new Float32Array(vectors[i]!)]),
        );
      }
    ```

<threat_model>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator code → MCPackEngine constructor | Operator passes `tools[]` and `config.embeddings.provider`; engine treats both as untrusted (validates parallel-array contract; never mutates `tools` array). |
| Engine → EmbeddingProvider callback | Provider is operator-controlled. Could throw, return malformed shape, or return oversized vectors. Engine validates and recovers via `.catch`. |
| Engine internal → semanticIndex Map | Map is `private` (TypeScript compile-time); written only by `buildSemanticIndex`; treated as read-only post-build by Phase 8 (next phase). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Information Disclosure | `console.warn` in build-failure `.catch` | mitigate | Log message uses provider's error text only — never includes tool names. Locked format: `` `MCPack: semantic index build failed: ${message}` ``. RBAC invariant from CLAUDE.md Quality Gate #5. |
| T-07-02 | Denial of Service | Build promise hangs (slow/deadlocked provider) | mitigate (graceful) | Build is detached; hanging build leaves `isIndexReady()` returning false forever; queries fall back to keyword automatically; gateway stays up. NO timeout logic added (would create new failure mode). |
| T-07-03 | Denial of Service | Malicious provider returns oversized vectors (e.g., 10⁹-dim) | accept | `Float32Array(10⁹)` would throw RangeError on most platforms; the throw is caught by `.catch`; build fails gracefully. Provider is operator-controlled — out of attacker's reach. |
| T-07-04 | Tampering | External code mutates `semanticIndex` post-build | accept | TypeScript `private` access modifier prevents accidental external write; bracket-access at runtime is technically possible but only from in-process operator code. Out of MCPack's threat model (the operator runs the engine). |
| T-07-05 | Repudiation | Gateway crashes silently after build failure | mitigate | `.catch` logs via `console.warn`; operators see the failure in their log stream. Phase 9 (analytics) will add structured event capture. |
| T-07-06 | Spoofing | Attacker calls private engine method to inject vectors | accept | `MCPackEngine` is not exposed to MCP clients (only the SDK Server is). Reaching engine privates requires in-process code, which is operator-trust scope. |
| T-07-07 | Tampering | Engine mutates caller's `tools[]` array in place | mitigate | Treat `tools` as read-only. `buildSemanticIndex` only iterates (`tools.map(...)` returns new array; `tools.length`, indexed reads). NO in-place sort/filter/splice. Pitfall 5 from RESEARCH. |
| T-07-08 | Information Disclosure | `unhandledRejection` from missing `.catch` crashes process and may dump stack with tool surface info | mitigate | `.catch` is attached in the SAME statement as the kickoff (Pitfall 2 from RESEARCH). No window where the promise is rejected without a handler. |
