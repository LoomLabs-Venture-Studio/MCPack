**Step 4: src/types.ts** -- All interfaces for the project.

CRITICAL type decisions from CONTEXT.md:
- `MCPackToolDefinition extends Tool` (from MCP SDK) adding `handler` for build mode
- `ToolIndexEntry` does NOT have a `tier` field (dropped per CONTEXT.md)
- `ToolIndexEntry` has `schemaKeywords: string[]` separate from `keywords: string[]` (per RESEARCH.md open question recommendation -- schema property tokens scored at SCHEMA_PROPERTY=1 weight, separate from KEYWORD=2 weight)
- `Session` includes `queryLog: Array<{ query: string, results: string[], timestamp: number }>`
- `SearchToolResponse` is minimal: `{ tools, total_available, showing, session_id }`
- `MCPackConfig` includes `defaultRole?: string`
- Import `Tool` type from `'@modelcontextprotocol/sdk/types.js'`

Public types (exported from index.ts):
- `MCPackConfig` -- config for wrap mode: `{ roles?: RoleConfig, defaultRole?: string, index?: IndexConfig, session?: SessionConfig }`
- `MCPackServerConfig` -- config for build mode: extends MCPackConfig adding `{ name: string, version: string, tools: MCPackToolDefinition[] }`
- `MCPackToolDefinition` -- extends `Tool` from MCP SDK adding `handler: (args: Record<string, unknown>) => Promise<ToolCallResult>`
- `RoleConfig` -- `{ [roleName: string]: string[] | '*' }`
- `IndexConfig` -- `{ maxResults?: number }` (default 5, max 10). Drop `mode` field from PRD -- not needed per CONTEXT.md simplification.
- `SessionConfig` -- `{ ttl?: number }` (default 7200000)
- `SearchToolResponse` -- `{ tools: SearchResult[], total_available: number, showing: number, session_id: string }`
- `SearchResult` -- `{ name: string, loaded: boolean, schema?: object }` (schema is the full tool JSON schema, present only when loaded=false)
- `ToolCallResult` -- `{ content: Array<{ type: string, text: string }>, isError?: boolean }`

Internal types (NOT exported from index.ts, only from types.ts):
- `ToolIndexEntry` -- `{ name: string, description: string, keywords: string[], schemaKeywords: string[], schema: object }`
  - `schema` stores the full Tool definition object for returning in search results
  - `keywords` are extracted from name + description (scored at KEYWORD=2)
  - `schemaKeywords` are extracted from inputSchema.properties names (scored at SCHEMA_PROPERTY=1)
- `Session` -- `{ id: string, role: string, loadedTools: Set<string>, queryLog: Array<{ query: string, results: string[], timestamp: number }>, createdAt: number, lastActiveAt: number }`

IMPORTANT: Use `.js` extension in all imports (ESM requirement). E.g., `import type { Tool } from '@modelcontextprotocol/sdk/types.js'`

Create `src/index-builder.ts` exporting a `buildIndex` function.

**Function signature:**
```typescript
export function buildIndex(tools: Tool[]): ToolIndexEntry[]
```

Where `Tool` is imported from `'@modelcontextprotocol/sdk/types.js'`.

**Implementation:**

1. Export a `tokenize(text: string): string[]` function (also used by search.ts later):
   - Split on camelCase boundaries: replace `/([A-Z])/g` with ` $1`
   - Lowercase everything
   - Split on `[_\-\s]+`
   - Filter out empty strings
   - Return array of tokens

2. Define stop words set (Claude's discretion per CONTEXT.md):
```typescript
const STOP_WORDS = new Set([
  'a', 'an', 'the', 'and', 'or', 'for', 'to', 'of',
  'in', 'on', 'at', 'by', 'with', 'from', 'is', 'are',
  'be', 'this', 'that', 'it', 'as', 'was', 'were', 'will',
  'can', 'has', 'have', 'had', 'do', 'does', 'did', 'not',
  'but', 'if', 'no', 'so', 'up', 'out', 'about', 'into',
  'than', 'then', 'each', 'which', 'their', 'there',
]);
```

3. `extractKeywords(name: string, description: string): string[]`:
   - Tokenize the name (camelCase + underscore split)
   - Tokenize the description: lowercase, split on whitespace, remove non-alphanumeric chars, filter words <= 2 chars, filter stop words
   - Combine and deduplicate via `new Set()`
   - Return array

4. `extractSchemaKeywords(inputSchema?: object): string[]`:
   - If inputSchema has `properties` (check with `'properties' in inputSchema`), iterate over `Object.keys(inputSchema.properties)`
   - Tokenize each property name using the same `tokenize()` function
   - Deduplicate and return

5. `buildIndex(tools: Tool[]): ToolIndexEntry[]`:
   - Map each tool to a `ToolIndexEntry`:
     ```typescript
     {
       name: tool.name,
       description: tool.description ?? '',
       keywords: extractKeywords(tool.name, tool.description ?? ''),
       schemaKeywords: extractSchemaKeywords(tool.inputSchema),
       schema: tool,
     }
     ```
   - Return the array

IMPORTANT: All imports use `.js` extension. `import type { Tool } from '@modelcontextprotocol/sdk/types.js'`

Export `tokenize` and `STOP_WORDS` as named exports (they are internal to the package but needed by search.ts).
