**Sub-step 2b — Author `docs/analytics.md` (NEW):**

Per RESEARCH §Pattern 5 outline. Sections in order:

1. **Why server-handle analytics (vs MCP wire)** — Gate 5 architectural invariant: `getAnalytics()` is on the returned handle, NOT exposed as an MCP tool. Agents cannot call it. Verified by `grep -E "setRequestHandler.*[Aa]nalytics" src/` returning zero matches
2. **The `getAnalytics(options?)` API** — signature `getAnalytics(options?: { role?: string }): AnalyticsSnapshot`; no-arg form returns operator-unscoped view; `{ role: 'cofounder' }` returns role-scoped view
3. **`AnalyticsSnapshot` shape** — full shape from `src/types.ts` (referenced from interfaces block above): `{ searches, calls, denials, misses, summary.byRole[role]: { searchCount, callCount, denialCount, missCount, topTools[5], deadTools[] } }`
4. **The four event types** — when each fires:
   - `search` — every `search_tools` invocation; records `{query, role, returnedTools, ts}`
   - `call` — every successful non-`search_tools` `tools/call`; records `{tool, role, ts}`
   - `denial` — every `tools/call` for a tool the role cannot access; records `{tool, role, ts}` BUT see privacy section below
   - `miss` — `search_tools` query that returns zero results
5. **Operator unscoped vs role-scoped — privacy semantics** — REQ-v11-analytics-privacy: a role-scoped query MUST NOT expose tools outside that role's allowed set. Denial events for a role-scoped query never reveal restricted tool names. Operator unscoped view sees everything.
6. **Dead-tool detection** — `summary.byRole[role].deadTools` lists tools that role can see but has zero `call` events for in the current process lifetime. Useful for trimming role configs.
7. **RBAC integrity invariant** — `getAnalytics()` is unreachable via MCP wire; agents calling `tools/call` with name `getAnalytics` get the standard `Unknown tool: getAnalytics` opaque-denial response (Gate 5)
8. **In-memory only; resets on process restart** — REQ-v11-analytics-storage; deliberately not persisted in v1.1; persistence (OTEL / file / webhook) is a v1.2 candidate
9. **Bounded retention** — `MCPackConfig.analytics.maxEvents` default 10,000 events; oldest dropped on overflow; configure for high-traffic deployments

Length target: ≥80 lines including code blocks.
