## Tasks

<task id="1" type="auto">
  <name>Author 50-query intent benchmark + runner + npm script</name>
  <behavior>
    A reproducible recall@5 measurement across 50 hand-authored intent queries
    targeting the Stripe MCP surface. The runner constructs both a v1.0
    keyword-only engine and a v1.1 hybrid engine over the same captured tool
    surface, drives `search_tools` through both, computes recall@5 over queries
    where at least one engine finds the expected tool (zero-information
    exclusion), and writes a JSON report. The hybrid recall@5 must be at least
    15 percentage points absolute above v1.0 keyword recall@5 (Gate 6b).
  </behavior>
  <implementation>
    - Create `test/harness/intent-benchmark-queries.json` with 50 entries: 10 easy /
      20 paraphrased / 10 abbreviation / 10 typo-or-partial. Each entry:
      `{ query, expectedTool, category }`. `expectedTool` names target the real
      Stripe MCP tool surface (28 tools).
    - Create `test/harness/intent-benchmark.ts`:
      - Spawn `@stripe/mcp` via `StdioClientTransport`, capture `tools/list`.
        Gracefully exit with `process.exit(0)` and a console message when
        `STRIPE_SECRET_KEY` is unset (matches stripe-harness.ts:55-59 pattern).
      - Build TWO `MCPackEngine` instances (imported from `../../src/core.js`):
        one with `embeddings` undefined (keyword-only), one with
        `embeddings: { provider: createMiniLMProvider() }` (hybrid). Wait for
        `engine.hasVectors()` true for the hybrid engine.
      - For each query: call `engine.handleSearchTools({ query: q, limit: 5 }, sessionId)`
        on both engines. Extract returned tool names. Compute recall@5: 1 if
        expectedTool ∈ top-5 ∋ result.tools.map(t=>t.name), else 0.
      - Skip queries where neither engine finds expectedTool (zero-information).
      - Write `test/harness/intent-benchmark-report.json` with: total_queries,
        valid_queries, keyword_recall_at_5, hybrid_recall_at_5,
        recall_improvement_pp, threshold_pp=15, passed boolean, by_category
        breakdown, generated_at.
    - Add `package.json` scripts: `"benchmark": "npx tsx test/harness/intent-benchmark.ts"`.
    - Add `.gitignore` entry: `test/harness/intent-benchmark-report.json`.
  </implementation>
  <verify>
    <automated>
      - `npx tsc --noEmit` clean.
      - `npm test` 234/234 still passing (Gate 4).
      - `grep -rE "@llvs/mcpack-embeddings|@huggingface/transformers|@xenova/transformers" src/ test/ --exclude-dir=harness` returns zero matches (Gate 3 REVISED).
      - When `STRIPE_SECRET_KEY` unset: `npm run benchmark` exits 0 with skip message.
      - When `STRIPE_SECRET_KEY` set: `npm run benchmark` writes report with hybrid_recall_at_5 ≥ keyword_recall_at_5 + 0.15 (Gate 6b).
    </automated>
  </verify>
</task>

<task id="2" type="auto">
  <name>Author real-MiniLM perf bench + npm script</name>
  <behavior>
    Real-MiniLM perf measurement against a synthetic 50-tool corpus.
    Measures index_build_ms (Gate 6d ≤ 5000ms), search_p99_delta_ms vs v1.0
    keyword baseline (Gate 6c ≤ 50ms), and vector_bytes (≤ 2,097,152 bytes
    per REQ-v11-perf-budget). Runs offline — no Stripe required.
  </behavior>
  <implementation>
    - Create `test/harness/perf-bench.ts`:
      - Generate 50 synthetic Tools with realistic name/description/inputSchema
        shape (deterministic seed for reproducibility).
      - Time `new MCPackEngine(tools, {})` keyword-only; run 100 search_tools
        calls (warm cache); compute p99.
      - Time `new MCPackEngine(tools, { embeddings: { provider } })` hybrid;
        wait for `hasVectors()` true (record build_ms = wait time);
        run 100 search_tools calls (warm cache); compute p99.
      - Compute search_p99_delta_ms = hybrid_p99 - keyword_p99.
      - Compute vector_bytes by summing Float32Array.byteLength across the
        engine's semanticIndex (use a tiny accessor via TypeScript `any` cast
        — engine.semanticIndex is private but accessible in test harness).
      - Write `test/harness/perf-bench-report.json`: index_build_ms,
        keyword_p99_ms, hybrid_p99_ms, search_p99_delta_ms, vector_bytes,
        gate_6c_passed, gate_6d_passed, gate_perf_memory_passed, generated_at.
    - Add `package.json` scripts: `"perf-bench": "npx tsx test/harness/perf-bench.ts"`.
    - Add `.gitignore` entry: `test/harness/perf-bench-report.json`.
  </implementation>
  <verify>
    <automated>
      - `npx tsc --noEmit` clean.
      - `npm run perf-bench` exits 0; report written.
      - `index_build_ms ≤ 5000` (Gate 6d).
      - `search_p99_delta_ms ≤ 50` (Gate 6c).
      - `vector_bytes ≤ 2097152` (REQ-v11-perf-budget memory).
    </automated>
  </verify>
</task>
